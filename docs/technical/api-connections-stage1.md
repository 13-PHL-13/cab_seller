# Подключения API: первый согласованный этап

19 ноября 2026. Основная ветка — `codex/client-review`. Этап с публикацией согласован Андреем. Текущий статус сборки следует смотреть в проверках Pull Request.

## Изменения

- Раздел «Настройки» в меню и заголовке называется «Подключения API». Адрес `/settings` и идентификаторы разрешений сохранены, вкладки ИИ, профиля и уведомлений остаются.
- ВБ: один токен. Ozon: обязательные Seller API (Client ID, API Key) и Performance API (отдельные Client ID, Client Secret) для каждого нового магазина.
- Уже существующий магазин Ozon можно дополнить через `PUT /api/marketplace/stores/:id/ozon-performance`. Сохранение перечитывает запись под блокировкой в транзакции и меняет только вложенную пару Performance; Seller API, ID и название сохраняются. Проверяются компания и доступ к магазину.
- Проверка Performance запрашивает краткосрочный токен у `https://api-performance.ozon.ru/api/client/token`; токен не возвращается клиенту и не сохраняется. Тексты ответов провайдера не раскрываются в ошибках. Сохранённая пара использует существующее AES-256-GCM-хранилище.
- Список магазинов возвращает только `performanceConnected`, без секретов или их фрагментов. Для старых записей без вложенного Performance возвращается false. Миграция таблиц не требуется.
- Новый магазин Ozon не перезаписывает одноимённую существующую запись. Обновление Performance выполняется отдельно по ID.
- Перенесены только 31 проверенный публичный материал v5: два видео, 23 иллюстрации, два постера, субтитры и главы. Приватные исходники и ранние версии не копируются.
- При добавлении магазина обновляется переключатель магазинов. Для отключения требуется явное подтверждение в карточке.

Рекламные отчёты этим этапом не реализованы: Performance API проверяет и сохраняет доступ для последующих функций.

## Проверки и границы

- 13 серверных модульных тестов: авторизация, финансовые агрегаты, валидация Performance, запрос токена, закрытые ошибки провайдера, шифрование обеих пар и права изменения подключений.
- Проверки TypeScript frontend и backend выполнены локально. Полная Linux-сборка выполняется GitHub Actions.
- Подключение реальных ключей и интеграционные проверки PostgreSQL не выполнялись локально. Для проверки действительного доступа используется серверная проверка при вводе ключей пользователем.
- Схема таблиц не меняется; существующий JSON с ключами расширяется вложенной парой Performance API.
- Клиентские модели и Zod получены из OpenAPI генератором Orval. Интерфейс использует слой `marketplace-api.ts`; существующие React-хуки сохранены.
- Другие страницы, расчёты дашборда, интерфейс ИИ и задачи этим этапом не заменяются. Ключи и тестовые учётные записи в репозиторий не включены.
