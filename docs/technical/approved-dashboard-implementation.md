# Реализация согласованного дашборда

## Источник интерфейса
В качестве визуального и функционального референса используется переданный архив «НАВИГАТОР.zip», пакет `Dashboard-node-v1`. Его исходные демонстрационные значения не являются финансовыми контрактами и не переносятся в расчёты рабочего кабинета.

## Что реализовано в этой ветке
- Переработана главная страница кабинета React в соответствии с компоновкой согласованного макета: фильтры, карточки KPI, графики, воронка, финансовая сводка, магазины и боковая панель помощника.
- Сохранены существующие серверные API-запросы и сессионная авторизация.
- Фильтр периода использует существующие периоды API: 7, 30 и 90 дней.
- График выручки строится только по данным API. Для компактного отображения берутся последние 14 точек выбранного периода.
- Список магазинов формируется из API подключений пользователя.
- Финансовые карточки показывают пустое значение до появления подтверждённых финансовых отчётов.
- Заказы показываются по площадкам только при наличии достоверных данных воронки. Исторический ряд заказов по дням не имитируется.
- Воронка показывает только те агрегированные показатели, которые фактически возвращает API.
- Боковая панель ИИ явно обозначена как демонстрационная; запросы не отправляются сторонней модели.

## Ограничения текущих API
1. API не предоставляет дневной ряд заказов, поэтому график заказов из макета заменён достоверной разбивкой по площадкам и пояснением об ограничении источника.
2. Финансовые API-отчёты, комиссии, логистика, себестоимость, реклама и дополнительные расходы пока не реализованы. Финансовые значения из макета намеренно не подставляются.
3. Поддерживаются только Wildberries и Ozon. Другие площадки из иллюстративных макетов не показываются как реально подключённые.
4. API Ozon пока не возвращает полный набор метрик воронки; UI не подменяет отсутствующие значения.
5. Сейчас на каждую площадку приходится одно подключение на пользователя. Поддержка нескольких магазинов одной площадки потребует изменения схемы и API.

## Тестовые ключи
Тестовые ключи из переданного архива не добавляются в Git. Репозиторий публичный. Их можно вводить в личном кабинете через экран настроек API: сервер проверяет ключи и сохраняет учётные данные в зашифрованном виде в PostgreSQL. Не вставляйте их в исходники, документацию, CI или публичные логи.
