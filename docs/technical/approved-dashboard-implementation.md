# Реализация согласованного дашборда

## Источник интерфейса
В качестве визуального и функционального референса используется переданный архив «НАВИГАТОР.zip», пакет `Dashboard-node-v1`. Его исходные демонстрационные значения не являются финансовыми контрактами и не переносятся в расчёты рабочего кабинета.

## Что реализовано в этой ветке
- Переработана главная страница кабинета React в соответствии с компоновкой согласованного макета: фильтры, карточки KPI, графики, воронка, финансовая сводка, магазины и боковая панель помощника.
- Сохранены существующие серверные API-запросы и сессионная авторизация.
- Фильтр периода использует существующие периоды API: 7, 30 и 90 дней.
- График выручки строится только по данным API. Для компактного отображения берутся последние 14 точек выбранного периода.
- Список магазинов формируется из API подключений пользователя.
- Финансовые карточки показывают пустое значение до появления подтверждённых финансовых отчётов.
- Заказы показываются по площадкам только при наличии достоверных данных воронки. Исторический ряд заказов по дням не имитируется.
- Воронка показывает только те агрегированные показатели, которые фактически возвращает API.
- Боковая панель ИИ явно обозначена как демонстрационная; запросы не отправляются сторонней модели.

## Ограничения текущих API
1. API не предоставляет дневной ряд заказов, поэтому график заказов из макета заменён достоверной разбивкой по площадкам и пояснением об ограничении источника.
2. Финансовые API-отчёты, комиссии, логистика, себестоимость, реклама и дополнительные расходы пока не реализованы. Финансовые значения из макета намеренно не подставляются.
3. Поддерживаются только Wildberries и Ozon. Другие площадки из иллюстративных макетов не показываются как реально подключённые.
4. API Ozon пока не возвращает полный набор метрик воронки; UI не подменяет отсутствующие значения.
5. Сейчас на каждую площадку приходится одно подключение на пользователя. Поддержка нескольких магазинов одной площадки потребует изменения схемы и API.

## Тестовые ключи
Тестовые ключи из переданного архива не добавляются в Git. Репозиторий публичный. Их можно вводить в личном кабинете через экран настроек API: сервер проверяет ключи и сохраняет учётные данные в зашифрованном виде в PostgreSQL. Не вставляйте их в исходники, документацию, CI или публичные логи.

## Финансовый этап: Wildberries (первый адаптер)

- Добавлен серверный endpoint `GET /api/marketplace/finance/wildberries?from=YYYY-MM-DD&to=YYYY-MM-DD`.
- Endpoint требует сессию пользователя, ищет подключение только по `ownerId`, расшифровывает ключ на сервере и не возвращает секреты.
- Запрашивается новый Finance API Wildberries: `POST https://finance-api.wildberries.ru/api/finance/v1/sales-reports/detailed`.
- Запрос выполняется вручную из страницы «Финансы», без фонового polling. Диапазон ограничен 31 днём; размер одной выборки — до 100 000 строк.
- UI показывает сырые суммы выбранных полей отчёта: `retailAmount`, `ppvzForPay`, `deliveryRub`, `storageFee`, `acceptance`, `penalty`, `additionalPayment`, `deduction`, `acquiringFee`, `ppvzReward`. Суммы агрегируются без смены знака из ответа API.
- Если получено 100 000 строк, результат помечается как потенциально неполный. Автоматическая пагинация не выполняется, так как финансовый API ограничивает частоту запросов.
- API-ключ должен иметь права категории «Финансы». Проверка подключения на текущем этапе подтверждает аналитические права отдельно; наличие Finance scope проверяется только реальным запросом отчёта.
- Отчёт реализации не называется чистой прибылью или суммой ближайшей выплаты. Себестоимость, налоги и рекламные расходы в нём не рассчитываются.
- Ozon financial adapter не включён: старые `/v3/finance/transaction/list` и `totals` отключены 8 сентября 2026 года. Для новой интеграции необходимо реализовать последовательный вызов `/v1/finance/accrual/postings`, `/types` и `/by-day` после проверки актуальных контрактов.

## Финансовый этап: Ozon (второй адаптер)

- Добавлен owner-scoped endpoint `GET /api/marketplace/finance/ozon?from=YYYY-MM-DD&to=YYYY-MM-DD`.
- Используется новый `POST https://api-seller.ozon.ru/v1/finance/accrual/by-day`; устаревшие `/v3/finance/transaction/list` и `totals` не вызываются.
- По контракту by-day принимает одну дату и возвращает `accruals` плюс `last_id`; сервер последовательно перебирает даты и страницы, не распараллеливает запросы.
- Период ограничен 7 днями, общее число страниц ограничено 50, число страниц на дату — 20. При повторе курсора или достижении предела запрос завершается ошибкой, чтобы не выдавать частичный отчёт за полный.
- Суммируется `total_amount.amount` ровно один раз на запись. Разбивка по `accrued_category`: `POSTING`, `ITEM`, `NON_ITEM`, `CONTAINER_FEES`, неизвестные категории — `other`. Суммы сохраняют знак, валюта берётся из ответа.
- Пропуски `total_amount.amount` считаются отдельно и не включаются в итог.
- UI выполняет выгрузку только вручную. Результат не называется чистой прибылью или суммой выплаты.
- Unit tests проверяют разбиение по категориям, отрицательные суммы, неизвестные категории и отсутствующие суммы.

## Учёт себестоимости (COGS): первый этап

- Добавлен личный справочник товаров: площадка (`Ozon`, `Wildberries` или общий артикул), артикул продавца/SKU, название и себестоимость одной единицы в RUB.
- Данные принадлежат пользователю через `owner_id` с внешним ключом на `users.id`. Все чтение, изменение, удаление и история фильтруются по текущему пользователю; API закрыт middleware сессии.
- Для пары пользователь + площадка + артикул действует уникальность. Повторное создание возвращает конфликт, а не перезаписывает товар.
- Изменения себестоимости сохраняются в `cogs_cost_history`; история не перезаписывается. Удаление товара удаляет его историю каскадно.
- Добавлены endpoints: `GET/POST /api/cogs`, `PUT/DELETE /api/cogs/:id`, `GET /api/cogs/:id/history`.
- В кабинете добавлена страница «Себестоимость» с созданием, редактированием, удалением и просмотром истории.
- Перед первым запуском на новой базе нужно применить обновлённую Drizzle-схему: из корня проекта выполнить `pnpm --filter @workspace/db push` при заданном `DATABASE_URL`. Команда синхронизирует таблицы `cogs_products` и `cogs_cost_history`; сначала применять на тестовой базе и сделать резервную копию существующей БД.
- Пока это только справочник себестоимости. Автоматическая загрузка каталога, импорт CSV/XLSX, сопоставление SKU с продажами/возвратами, история себестоимости на дату продажи, реклама, налоги и расчёт маржи/прибыли не включены. Поэтому финансовая страница пока не показывает «чистую прибыль».
