# Компании, магазины и задачи

Данные и интеграции остаются в основном приложении. Демонстрационный архив использован как источник пользовательских сценариев, а не как база данных или код для замены сайта.

## Реализовано

- Для существующих и новых аккаунтов есть компания-владелец. Существующие карточки товаров, история себестоимости, расходы и ключи площадок мигрируются в личную компанию.
- У пользователя может быть несколько компаний; активная компания хранится в его серверной сессии. Все API-запросы каталога, финансов, подключений и ИИ ограничены активной компанией.
- Добавлены роли владельца, администратора, руководителя и сотрудника, ограничения разделов, финансов, редактирования себестоимости, задач и доступа к конкретным магазинам.
- Приглашения привязаны к email, отправляются письмом и действуют 7 дней. Принять приглашение может только вошедший пользователь с совпадающим подтверждённым адресом. Владелец и администратор видят участников и могут отзывать приглашения/удалять участников.
- Компания может подключать несколько кабинетов Ozon и Wildberries с отдельными именами. Фильтр кабинета находится в верхней панели; режим всех магазинов суммирует данные на дашборде и в финансовых отчётах.
- Добавлен список задач с исполнителем, сроком, приоритетом, статусами, передачей, архивом и обсуждением.
- История ответов ИИ хранится на сервере в привязке к компании и контексту дашборда; новый чат начинает отдельную историю.

## Обновление существующей базы

Перед запуском новой версии на базе с данными сделайте резервную копию PostgreSQL и один раз примените миграцию к базе из `DATABASE_URL`:

```powershell
node --env-file=artifacts/api-server/.env lib/db/scripts/apply-company-workspaces.mjs
```

Скрипт выполняет SQL в транзакции. Он создаёт компании, переносит существующие строки по владельцу, добавляет задачи и историю ИИ. Не запускайте `drizzle-kit push --force` вместо этой миграции: это не backfill существующих данных.

На новой пустой базе таблицы можно создать штатной командой `pnpm --filter @workspace/db push`.

После миграции перезапустите API и соберите frontend как обычно. Ключи маркетплейсов и ИИ не раскрываются приглашённым: в общую компанию передаются API-запросы через серверное шифрованное хранилище.

## Элементы из макета, которые остаются следующим этапом

Публичная маркетинговая страница, расширенная загрузка себестоимости из XLSX с распределением стоимости поставок, и дополнительные маркетплейсы требуют отдельной проработки. Предварительная минимальная цена рассчитывается по себестоимости каталога и фактической доле выплат от выручки за последний полный месяц; это ориентир, а не гарантированная цена. Архивные фиктивные продажи и демонстрационные суммы в расчёты не добавлялись.
